The Problem
What happens when we DON'T use OOP

Managing Data Without OOP

Imagine tracking students. Without OOP, you use separate variables for every student — or worse, parallel lists where the connection is fragile.

# 3 students → already 9 variables. 100 students → 300!
student1_name  = "Alice"
student1_age   = 20
student1_grade = "A"

student2_name  = "Bob"
student2_age   = 22
student2_grade = "B"
300 vars for 100 students
easy to mix up
impossible to scale

Why Parallel Lists Don't Work Either 😤

THE FRAGILE APPROACH
# Three parallel lists — connected by INDEX
names  = ["Alice",  "Bob",  "Charlie"]
ages   = [20,      22,    21]
grades = ["A",     "B",   "C"]

# Someone accidentally inserts "Diana" at index 1 in names...
names.insert(1, "Diana")
# NOW: names[1]="Diana", ages[1]=22 (Bob's age!)
# Diana's age is WRONG — we destroyed the connection!
⚠️ One insertion breaks the link between all three lists. This is a real bug that causes silent, hard-to-find errors.
THE OOP SOLUTION
# Each student is ONE object — data stays together
class Student:
    def __init__(self, name, age, grade):
        self.name  = name
        self.age   = age
        self.grade = grade

s1 = Student("Alice",   20, "A")
s2 = Student("Bob",     22, "B")
# s1.name, s1.age, s1.grade ALWAYS belong to Alice
# s2.name, s2.age, s2.grade ALWAYS belong to Bob
✅ Name, age, and grade are bundled into one object. They can never get separated.

What is OOP?
Bundle data + behaviour into one unit

The Big Idea

OOP = Object-Oriented Programming.
Instead of scattered variables, you bundle related data and behaviour together into a single unit — an Object.

ATTRIBUTES — data the object knows  →  name, age, grade
METHODS — things the object can do  →  introduce(), study()
CLASS = blueprint / template
OBJECT = a real thing from the blueprint
one class → unlimited objects

OOP Vocabulary — 4 Words You Must Know 📖

CLASS
The blueprint / template. Describes what every object of this type will have.
Dog    Student    BankAccount    Car
OBJECT / INSTANCE
A real, actual thing created FROM a class. Each one is independent.
rex    alice    my_account    car1
ATTRIBUTE
Data stored inside an object. Accessed via dot notation.
rex.name    alice.grade    car.speed
METHOD
A function that belongs to a class. Called via dot notation.
rex.bark()    alice.study()    car.drive()
💡 "Dog" is the class. "Rex" is an instance. Rex's colour & breed are attributes. Rex.bark() is a method.

Classes & Objects
Define the blueprint. Build the real things.

Your First Class

Define a class with the class keyword. The name uses PascalCase — each word capitalised. Use pass for an empty body.

# Define the class (the blueprint)
class Dog:
    pass         # empty body — does nothing yet

# Create objects (instances) from the class
rex   = Dog()    # rex is one Dog object
buddy = Dog()    # buddy is a different Dog object

print(rex)       # <__main__.Dog object at 0x...>
print(rex is buddy)   # False — different objects!
class Name: (PascalCase)
variable = ClassName()
one class → many objects

Defining a Class — What Goes Where 🏗️

CLASS SKELETON
class Dog:
# all methods go here
# all indented 4 spaces
pass
class — the keyword (like def for functions)
Dog — the name in PascalCase
: — colon required (just like if/for/def)
pass — placeholder for empty body
DOT NOTATION — ACCESS ANYTHING
class Dog:
    pass

# Create objects:
rex = Dog()

# Set attributes manually (dot notation):
rex.name  = "Rex"
rex.breed = "Labrador"
rex.age   = 3

# Read them:
print(rex.name)   # Rex
print(rex.age)    # 3
💡 This manual approach works but is fragile — you might forget to set an attribute. That's why we use __init__ (next!).

__init__
The Constructor — sets up every object safely

The Constructor

__init__ is a special method Python calls automatically the moment you create a new object. You never call it yourself — Python does it for you.

class Dog:
    def __init__(self, name, age):    # ← Python calls this automatically
        self.name = name             # attach to the object
        self.age  = age

rex = Dog("Rex", 3)    # __init__ fires instantly
print(rex.name)          # Rex  ← set by __init__
print(rex.age)           # 3   ← set by __init__
called automatically on creation
never call it yourself
sets up all attributes safely

__init__ — What Actually Happens Step by Step ⚙️

THE CODE
class Dog:
    def __init__(self, name, age):
        self.name = name
        self.age  = age

rex = Dog("Rex", 3)
Default values work too:
def __init__(self, name, age=1):
Then Dog("Rex") uses age=1 automatically.
STEP-BY-STEP TRACE
Step 1 Python creates a new empty Dog object in memory
Step 2 Python calls __init__(new_obj, "Rex", 3)
         → self = new_obj, name = "Rex", age = 3
Step 3 self.name = "Rex" → stored on the object
Step 4 self.age = 3   → stored on the object
Step 5 __init__ finishes
Step 6 rex now has .name and .age ready to use!
📌 __init__ is called automatically — you NEVER write Dog.__init__(rex, "Rex", 3) yourself. Just write rex = Dog("Rex", 3).

Understanding self — The Secret Ingredient ⚙️

WHAT IS self?
self = "this specific object".
When you call rex.bark(), Python passes rex as self automatically.
self.name = name means:
"On THIS object specifically, store a name attribute."
self.name → lives on the object permanently
name (no self) → local param, gone after __init__
self IN ACTION
class Cat:
    def __init__(self, name):
        self.name = name  # stored on the object

whiskers = Cat("Whiskers")
luna     = Cat("Luna")

# Each has its OWN .name:
print(whiskers.name)  # Whiskers
print(luna.name)      # Luna

# Changing one does NOT affect the other:
whiskers.name = "Shadow"
print(whiskers.name)  # Shadow
print(luna.name)      # Luna  ← unchanged!

Methods

What Is a Method?

A method is a function defined inside a class. It always takes self as its first parameter and is called using dot notation.

class Dog:
    def __init__(self, name):
        self.name = name

    def bark(self):          # ← METHOD (function in a class)
        print(f"{self.name} says: Woof!")

rex   = Dog("Rex")
buddy = Dog("Buddy")
rex.bark()     # Rex says: Woof!
buddy.bark()   # Buddy says: Woof!
def method(self): inside class
object.method() to call
self = the specific object

Methods — Full Anatomy 🎬

class BankAccount:
def __init__(self, owner, balance):
self.owner = owner
self.balance = balance
def deposit(self, amount):
self.balance += amount
def get_balance(self):
return self.balance
self — always the first param. Never passed by the caller. Python handles it.
self.balance — accesses this object's balance attribute.
return — sends a value back to the caller, just like a function. 
acc = BankAccount("Alice", 500)
acc.deposit(200)           # balance → 700
print(acc.get_balance())    # 700

Methods — Modify State & Return Values 🎬

MODIFY STATE — change the object's own data
class TrafficLight:
    def __init__(self):
        self.colour = "red"

    def next_light(self):      # changes self.colour
        if   self.colour == "red":
            self.colour = "green"
        elif self.colour == "green":
            self.colour = "yellow"
        else:
            self.colour = "red"

light = TrafficLight()
light.next_light()  # → green
light.next_light()  # → yellow
light.next_light()  # → red
RETURN VALUES — methods that give back data
class Rectangle:
    def __init__(self, w, h):
        self.w = w
        self.h = h

    def area(self):           # returns a value
        return self.w * self.h

    def is_square(self):      # returns True/False
        return self.w == self.h

r = Rectangle(5, 5)
print(r.area())        # 25
print(r.is_square())   # True
print(r.area() * 2)   # 50 — use the return value!

Putting It Together — Full BankAccount Example 🏦

class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner   = owner
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount
        print(f"Deposited {amount}. Balance: {self.balance}")

    def withdraw(self, amount):
        if amount > self.balance:
            print("Not enough money!")
        else:
            self.balance -= amount
            print(f"Withdrew {amount}. Balance: {self.balance}")

    def show(self):
        print(f"{self.owner}: Rs.{self.balance}")
# Create two accounts:
alice = BankAccount("Alice", 1000)
bob   = BankAccount("Bob")       # balance=0

# Use methods:
alice.deposit(500)      # 1500
alice.withdraw(200)     # 1300
bob.deposit(300)        # 300
bob.withdraw(500)       # Not enough!

alice.show()   # Alice: Rs.1300
bob.show()     # Bob:   Rs.300
✅ __init__ sets up every account safely
✅ Methods handle behaviour (deposit, withdraw)
✅ alice and bob have independent balances

Common Mistakes — Don't Fall For These! ⚠️

❌ Forgetting self in a method
def bark(): ← missing self → TypeError
def bark(self): ← correct ✅
Every method must have self as its first param
❌ Using name instead of self.name
self.name = name ← stores on object ✅
name = name       ← local var, gone! ❌
Without self, it's just a local variable
❌ Calling __init__ yourself
dog.__init__("Rex", 3) ← never do this! ❌
dog = Dog("Rex", 3)     ← correct ✅
Python calls __init__ automatically when you create an object
❌ Lowercase class names
class dog: ← not convention ❌
class bankaccount: ← hard to read ❌
class BankAccount: ← correct ✅
Class names always use PascalCase
